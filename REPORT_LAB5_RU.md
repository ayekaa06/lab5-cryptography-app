# Лабораторная работа №5 — Let's make a cryptography app

## Цель
Реализовать демонстрационное приложение с двумя близкими к реальным сценариями применения криптографии, протестировать его и изучить отдельное бесплатное ПО с открытым исходным кодом.

## Сценарий 1. Хранение паролей
Приложение хранит не исходный пароль, а результат Argon2id. Алгоритм создаёт случайную соль и параметры вычисления включает в строку хеша. При проверке вводимый пароль сверяется с сохранённым хешем.

Почему не SHA-256 для паролей: быстрые хеш-функции позволяют проверять большое количество догадок. Argon2id предназначен для хеширования паролей и увеличивает стоимость перебора.

## Сценарий 2. Шифрование файлов
Приложение шифрует файл с помощью AES-GCM. Ключ длиной 256 бит получается из парольной фразы с помощью scrypt и случайной соли. Для каждой операции шифрования генерируется случайный 96-битный nonce. AES-GCM обеспечивает конфиденциальность и аутентификацию шифротекста. При неверном пароле или изменении данных расшифрование завершается ошибкой.

В формате файла сохраняются версия формата, название KDF, соль, nonce и шифротекст с тегом аутентификации. Пароль и производный ключ не сохраняются.

## Запуск

Требуется Python 3.10+.

```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows:
# .venv\Scripts\activate
pip install -r requirements.txt
```

Хеширование и проверка пароля:

```bash
python app.py hash
python app.py verify '$argon2id$...'
```

Зашифровать и расшифровать файл:

```bash
python app.py encrypt notes.txt notes.enc.json
python app.py decrypt notes.enc.json notes-restored.txt
```

Команды интерактивно запрашивают пароль. Не передавайте реальные пароли в `--password`, так как аргументы командной строки могут сохраняться в истории или быть видны другим процессам.

## Тестирование приложения

```bash
python -m unittest -v
```

Тесты проверяют:
1. Успешную проверку правильного пароля и отказ для неправильного.
2. Разные хеши одного пароля за счёт случайной соли.
3. Цикл шифрования/расшифрования с восстановлением исходных байтов.
4. Отказ при неправильном пароле.
5. Отказ при изменении зашифрованных данных.

## Тест стороннего ПО с открытым исходным кодом: age

`age` — небольшой инструмент для файлового шифрования с открытым исходным кодом. Для демонстрации можно проверить шифрование/расшифрование тестового файла с парольной фразой (не используйте реальные секреты в учебной демонстрации).

Пример команд после установки `age`:

```bash
age --passphrase --output sample.age sample.txt
age --decrypt --output sample-restored.txt sample.age
cmp sample.txt sample-restored.txt
```

Во время тестирования была проверена версия age v1.3.2. Файл sample.txt был зашифрован в sample.age, затем восстановлен в sample-restored.txt. Команда diff sample.txt sample-restored.txt не вывела различий, что подтверждает совпадение исходного и восстановленного файлов.

## Вывод
Реализованы два сценария: хеширование паролей с Argon2id и аутентифицированное шифрование файлов с AES-GCM. Автотесты проверяют правильные и ошибочные сценарии. Дополнительная проверка age демонстрирует использование готового криптографического инструмента.
